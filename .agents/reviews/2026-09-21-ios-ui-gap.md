# iOS 原生版 vs Web 版 UI 差距报告(2026-09-21)

> 起因:用户反馈"UI 差距不应该那么大"。原生版概览等页面目前是纯系统默认样式(systemGroupedBackground + List),与 Web 版的深色玻璃设计系统观感差距明显。本报告逐页对照,给出**可执行的 SwiftUI 收敛建议**。
> 原则:**只收敛"页面内容区"(卡片、色板、排版、密度),不碰 tab bar / 导航栏等系统材质**——iOS 26 液态玻璃 tab bar 是原生线卖点,必须保留。

---

## 0. 结论摘要

- 差距的主因不是"页面结构"(两边信息架构已一致),而是四个内容区要素:**卡片质感(无边框/无投影)、语义色(系统红/绿/teal vs Web 的玫红/翡翠/天蓝)、数字排版(小号默认字体 vs 大号 tabular 圆体)、行样式密度(日志行缺色条/耗时/qtype 彩标)**。
- 深色模式下页面底色两边其实很接近(系统 `systemGroupedBackground` 深色 ≈ 纯黑,Web 为 `#060608`),真正拉开观感的是卡片层:`#1C1C1E` 无边框 vs `#121419` + 1pt 白 8% 边框 + 24px 圆角。
- Top5 立即采纳项(全部不动系统 chrome):统一卡片背景修饰器、语义色 token 化、统计块排版、日志行卡片流、胶囊分段控件。详见 §5,预计一天内可完成 1–3 项。

## 2. 约束(收敛建议必须在此框架内)

1. **蓝图红线**:`docs/IOS_NATIVE_PLAN.md` §5.4 —— "视觉对齐系统原生(iOS 26 系统自带样式优先),不要把 Web 版的 CSS 参数(透明度/圆角比例)硬搬进 SwiftUI——先用系统默认,再按用户反馈微调。" 用户本次反馈即属于该条所说的"按用户反馈微调"阶段,但**调整方式要翻译成 iOS 语言**(资产目录色、ShapeStyle、`continuous` 圆角),不是搬运 CSS 透明度/玻璃参数。
2. **性能红线**(同 Web 版教训,`PROJECT_MEMORY.md` §4):iOS 上大面积实时模糊/背板材质会发热掉帧。**卡片一律纯实色 + 细边框,不上 `.ultraThinMaterial`/`glassEffect`**;模糊只留给系统 chrome(tab bar、导航栏、Sheet)。
3. **动效克制**:不加大幅度,不新增弹性动画;最多用 `matchedGeometryEffect`(分段滑块)、`contentTransition(.numericText())`(数字滚动)这类系统级小动效。
4. **无障碍**:自定义卡片/胶囊控件必须继续支持 Dynamic Type(用语义字体 `.headline/.footnote` 而非大量写死 pt;确需写死处加 `minimumScaleFactor`),深浅色都用资产色自适应。
5. 用户偏好:中文文案、无宣传语;改前先拿真机/模拟器截图对照验收。

## 3. 设计 token 对照(差距的根源)

### 3.1 颜色

| 语义 | Web 深色(`src/index.css`) | 原生现状 | 差距 |
| --- | --- | --- | --- |
| 页面底色 | `#060608` 纯黑 + 极淡环境光晕 | `systemGroupedBackground`(深≈#000,浅=#F2F2F7) | 深色几乎无差;浅色 Web 底更冷更浅 |
| 卡片底 | `#121419` 纯实色 | `secondarySystemGroupedBackground`(深≈#1C1C1E,浅=白) | 深色略浅、无质感层次;关键缺边框 |
| 卡片边框 | 1px `rgba(255,255,255,0.08)`(强 0.14) | **无** | **高**:深色下卡片与底分离感全靠它 |
| 强调色 | `#34D399` 翡翠绿 | 资产绿 ≈ #34AA7A / #41BB85 | 中:偏"系统绿",少翡翠感 |
| 拦截/危险 | `#FB7185` 玫红(soft 14%) | `.red`(systemRed 纯正红) | **高**:玫红更柔和,全站语义一致 |
| 信息/耗时 | `#38BDF8` 天蓝 | `.teal` | **高**:图表/徽标/耗时全在用 |
| 警告 | `#FBBF24` 琥珀 | `.yellow` | 中 |
| 重写 | `#A78BFA` 紫 | `.orange`(ReasonBadge) | **高**:语义错位(Web 重写=紫,原生=橙) |
| 成功 | `#4ADE80` | `.green` | 低 |
| 文字层级 | t1 白 94% / t2 64% / t3 40% | `.primary/.secondary/.tertiary` | 低(系统已够) |

### 3.2 形状与排版

| 项 | Web | 原生现状 | 差距 |
| --- | --- | --- | --- |
| 卡片圆角 | 大卡 24px(rounded-3xl)、统计块 16px、防护主卡 28px、分组 22px | 16 / 20 / 22 混用,无规范 | 低(接近,统一即可) |
| 数字 | `tabular-nums` + 22px bold,语义着色 | `.title3`(20pt)bold,部分用 `.primary` 黑 | **中高**:大数字是仪表盘观感核心 |
| 卡片投影 | 深色 `0 16px 48px -12px rgba(0,0,0,.55)` | 无 | 低(深色实色卡可省;浅色可加极淡) |
| 图标气泡 | 行首 36px 圆角方块,语义色 14% 底 | 无(过滤器/设置页纯文字行) | **高**(结构性密度差) |

### 3.3 全局 chrome(对照结论:保留原生)

| 项 | Web | 原生 | 结论 |
| --- | --- | --- | --- |
| 标签栏 | 自绘胶囊玻璃 + 透镜动效(模仿 iOS 26) | **系统真液态玻璃** + `tabBarMinimizeBehavior(.onScrollDown)` | 原生胜,保留(§6) |
| 顶栏 | 悬浮玻璃胶囊"防护运行中 | AdGuard Home Console"(红/绿脉冲点) | 无对应物 | 可选收敛(§4.2,G3,中低优先) |
| 页面标题 | 26px 粗体行内大标题 | `.navigationTitle` 大标题(滚动折叠) | 保留原生 |
| 搜索/下拉刷新 | 自绘 SearchBar + 下拉 | `.searchable` / `.refreshable` | 保留原生 |

## 4. 逐页差距与建议

优先级标注:[高] 观感差距大且低风险;[中] 有差距或有一定实现成本;[低] 锦上添花。风险标注其与"系统原生优先"约束的冲突程度。

### 4.1 概览页(`OverviewView.swift` vs `.agents/evidence/web/02-overview.png`、`06-overview-bottom.png`)

**Web 实拍要点**:纯黑底;防护主卡(翡翠 20% 渐变叠 `#15171D` 实色 + 1pt 边框,28px 圆角,开关/双胶囊按钮);2×2 统计块(实色卡 16px 圆角,数值 22px bold:查询=翡翠绿、已拦截=玫红、耗时/客户端=天蓝,`tabular-nums`);流量趋势卡(查询=翡翠面积图,拦截=**天蓝**细线,虚线网格,标题旁胶囊范围选择器);请求构成环形图;Top 榜单卡(胶囊分段 + 三列 BarList:名称/7px 细条/右对齐数值,"查看更多"玻璃按钮);上游服务器卡(图标气泡 + 天蓝 info 徽标);底部 3 列服务器信息卡。顶部悬浮状态胶囊。

### 4.2 日志页(`QueryLogView.swift` vs `.agents/evidence/web/03-log.png`、`07-log-scrolled.png`)

### Top1 统一卡片修饰器(影响所有页面,观感差距最大单一来源)

extension View {

    func agCard(cornerRadius: CGFloat = 20, padding: CGFloat = 0) -> some View {

## 6. 建议保持原生、不作收敛的点(及理由)

1. **标签栏(iOS 26 液态玻璃 + 透镜滑动 + `tabBarMinimizeBehavior`)**:Web 版胶囊透镜就是对它的模仿;原生是"参照物"而非"追赶者"。改动只会引入发热风险(Web 版已把大面积 backdrop-filter 列为性能红线)。
2. **导航大标题折叠 / `.searchable` / `.refreshable`**:系统交互肌肉记忆,Web 版是自绘近似,无需反向对齐。
3. **Toggle / Menu / Sheet(presentationDetents)/ contextMenu 长按**:蓝图 §3 明确"恢复原生长按"是原生优势;Web 禁长按是 Safari 妥协,不要把"显式按钮"搬回去。
4. **系统深浅色切换与 Dynamic Type**:自定义色 token 必须带 light/dark 双值;凡写死字号处控制最小粒度,保证辅助功能字号下不破版。
5. **加载/空态(ProgressView、系统骨架)**:Web 的 shimmer 骨架不必复刻;系统 Spinner 足够克制。
6. **触觉反馈**:原生已有;不要为对齐 Web 的 WAAPI 动画增加额外动效(Web 侧动效幅度是用户定稿的克制值,原生更不应加码)。
