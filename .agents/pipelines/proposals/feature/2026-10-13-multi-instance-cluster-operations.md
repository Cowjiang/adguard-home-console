# 多实例运维能力闭环套件（P1: 订阅列表同步、客户端同步与健康矩阵面板）

**Class:** feature
**Status:** implemented
**Date:** 2026-10-13
**Source:** 演进路线图 P1 阶段综合提案；对标多机（主备 DNS / 旁路由）部署运维核心痛点

## Goal

在当前项目中，多实例环境已完成了「全局数据聚合 (Overview Stats)」、「集群级防护并发控制 (Cluster Protection)」以及「DNS 重写与自定义规则单向同步 (Rules Sync)」的基底功能。
然而在实际的多节点部署中，用户依旧面临三大核心运维断层：
1. **订阅源割裂**：阻断规则订阅列表（Filter Lists，含第三方广告源 URL、名称、启用状态）需要在各节点重复手动配置；
2. **设备识别不一致**：局域网终端向不同 DNS 分流请求时，由于客户端定义（Clients，含别名、阻止服务与标签）未对齐，导致控制台设备名识别混乱、策略无法统一；
3. **节点感知分散**：缺乏全景视图快速掌握各个节点的探活延迟（RTT）、在线健康状态、版本一致性与核心防护开关差异。

本提案将上述 P1 阶段的三项能力合并为一个**多实例运维闭环套件**，一次性补齐多节点配置同步与集群状态全景感知。

## Decision

### 1. 模块一：过滤规则订阅列表（Filter Lists）单向同步
- **数据源与契约**：
  - 读取源实例 `GET /filtering/status` 中的 `filters: Filter[]`（黑名单订阅）与 `whitelist_filters: Filter[]`（白名单订阅）。
- **同步算法与下发**：
  - 按订阅源 `url` 作为唯一主键比对目标实例列表：
    - 针对目标节点已存在的相同 `url`：比对并更新其 `name` 与 `enabled` 状态。
    - 针对目标节点缺失的订阅：调用 `POST /filtering/add_url` 追加添加。
    - 容错支持：订阅 URL 仅推送配置，由各实例 AGH 自行异步拉取规则内容，不传输体积庞大的规则文本。
- **UI 交互**：
  - 在「过滤器 / 规则列表」页面右上角工具栏展示「同步到其他实例」入口（仅在 `instances.length > 1` 时暴露），支持勾选是否包含白名单规则。

### 2. 模块二：静态客户端定义与标签（Clients & Tags）同步
- **数据源与契约**：
  - 读取源实例 `GET /clients`（包含静态配置的 `clients: Client[]`）。
  - 每个 Client 包含：`name`、`ids`（IP、MAC、CIDR）、`blocked_services`、`tags`、`upstreams` 等核心策略字段。
- **差异识别与写入**：
  - 以 `name` 或主要绑定 `id`（MAC/IP）为比对标识：
    - 目标端已存在同名客户端：调用 `POST /clients/update` 更新其别名、阻止服务与标签。
    - 目标端缺失的客户端：调用 `POST /clients/add` 追加写入。
  - 范围限制：仅同步用户静态录入的持久化客户端定义，不强行覆盖各节点底层 DHCP 动态分配的临时租约。
- **UI 交互**：
  - 在「客户端（Clients）」页面顶部工具栏增加同步操作，支持多选目标实例与确认提示。

### 3. 模块三：集群健康度与延迟矩阵面板（Cluster Health Matrix）
- **指标扩展与探活**：
  - 扩展 `src/lib/session/probe.ts`，在探活各节点时记录并暴露网络往返耗时（`latencyMs`）。
  - 结合各实例 `/control/status`，汇总核心运行指标：`version`（版本号）、`protection_enabled`（防护开关）、`parental_control` 等状态。
- **全景 UI 呈现**：
  - 在桌面端概览页顶部及移动端实例切换抽屉中，提供「集群健康矩阵」卡片：
    - 🟢 **健康**：在线、网络时延正常、核心开关与主实例一致。
    - 🟡 **注意**：各节点 AGH 核心版本不一致，或核心防护开关状态不同步。
    - 🔴 **异常**：节点离线不可达、或 401 凭据失效。
  - 紧凑展示各节点标签、实时延迟数值、一键快速跳转与全量刷新。

## Scope Boundaries

- **性能约束**：所有同步操作均由用户在前端主动触发或低频轮询，不引入常驻后台进程或外部存储，严格维持前端无状态优先的设计原则。
- **容错隔离**：针对集群中部分处于离线或鉴权失败的节点，执行跳过并收集告警信息，绝不阻断其他正常在线节点的同步流程。

## Accept

- [x] **订阅列表同步**：在规则列表页支持将黑白名单订阅源 URL、名称及开关状态精准镜像或增量推送到目标实例。
- [x] **客户端定义同步**：在客户端管理页支持将静态设备的别名、阻止服务和标签同步到目标节点，具备新增与更新区分处理能力。
- [x] **健康度矩阵面板**：在概览或实例切换界面提供包含 RTT 延迟、版本一致性与防护状态比对的健康指示视图。
- [x] **健壮容错**：任一节点故障、网络中断或鉴权失效时提供清晰的差异化反馈，保障成功节点的变更生效与 SWR 缓存及时刷新。
- [x] **自动化测试覆盖**：为订阅列表差异比对、客户端更新映射以及健康度聚合计算补充完备的单元测试用例。
