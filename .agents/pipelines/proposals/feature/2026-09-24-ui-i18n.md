# 为 React UI 引入中英双语

**Class:** feature
**Status:** proposed
**Date:** 2026-09-24
**Updated:** 2026-09-25（阶段一、二完成：时长/相对时间未用 Intl.RelativeTimeFormat，改为词典复数以保持 zh 输出逐字不变；兜底语言由 zh 改为 en，见 Decision。阶段二实际迁移 19 个文件、约 480 条文案，词典扩至 14 个域；审计后 src/ 无残留硬编码 UI 中文）
**Source:** 用户要求（「我准备进行i18n的工作」）；语言范围（中+英）、实现库（react-i18next）、节奏（分阶段）经用户确认。

## Goal

把 React UI（Web/PWA 与 Tauri 壳共用同一前端）的硬编码中文文案迁入 i18n 体系，新增英文。用户可在设置中切换语言，默认跟随系统；中文仍是基准语言（key 语义以中文为准）。仓库文档、代码注释与 commit 规范不变（仍中文 / 英文 conventional），不属于本次范围。

现状盘点（2026-09-24）：

- `src/` 39 个 TS/TSX 文件全部含中文，带引号的含中文字符串字面量约 608 处（含少量注释，量级以此为准），无任何 i18n 基础设施。
- `src/lib/format.ts` 全部硬编码 `zh-CN` 与中文单位（天 / 小时 / 分钟 / 秒 / 刚刚 / 从未）。
- `src/lib/constants.ts` 的 `REASON_META`（AGH 拦截原因枚举→标签）与 `LOG_FILTERS` 是跨页共享文案源；`src/lib/navMeta.ts` 的 tab 标题会传入原生 tabbar，`nativeHeaderAction`、`usePick` 原生选择器也有文案越 JS 边界传入原生层的点，i18n 必须覆盖这些传参处。
- `index.html` 为 `lang="zh-CN"`、中文标题与 description，已有主题的首帧引导脚本（localStorage + 内联 JS）可作语言引导的样式先例。

## Decision

- **库**：`i18next` + `react-i18next`。词典按域拆文件放 `src/lib/i18n/`（工具层，目录内含初始化入口与语言资源，资源按域分文件）；中文缺 key 即视为漏迁（dev 下告警）。
- **语言解析**：localStorage 显式设置（key 风格沿用主题，`agh.console.lang.v1`）→ `navigator.languages` 匹配 → `en` 兜底（2026-09-25 应用户要求由 zh 改为 en，`index.html` 静态默认同步）；切换入口放设置页。
- **首帧引导**：`index.html` 内联脚本在首帧前设置 `<html lang>` 与文档标题，防刷新闪中文/字体跳变；引导只读存储键，不加载词典。
- **格式化**：`format.ts` 改走 `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` 并接收当前 locale；中文单位词入词典。`zh-CN` 现值即 zh 语言行为，en 走对应 Intl 输出。
- **常量文案**：`REASON_META`、`LOG_FILTERS`、`navMeta` 等共享文案改存 key，展示层经 `t()` 翻译；原生传参处在组参时取当前语言文案。
- **不迁移**：注释、`docs/`、commit message、`server/`（Express 代理无 UI 文案）。
