# 收干净 Rust 壳与插件 fork 的失修项：失效配置、构建生成物与不可复现的 delta

**Class:** simplification
**Status:** proposed
**Date:** 2026-10-07
**Source:** 2026-10-07 src-tauri/ 侧优化调查（用户要求"对 rust 的部分进行优化调查"）；量化证据见本页 Note

## Goal

`src-tauri/` 总量不大（核心代理 715 行，其中生产代码约 276 行；插件 fork 66 个跟踪文件、约 5,000 行原生代码），但边界上有四类失修项，逐条已实测：

1. **插件 fork 的基线不可复现**：真正的 delta 只有约 200 行（全为加法），却没有任何可执行的记录——唯一线索是 `Cargo.toml` 的一段注释和 `.cargo_vcs_info.json` 的 sha1；上游再发版时只能凭记忆手工重做。
2. **构建生成物与 crates.io 解包残留被跟踪**：`permissions/autogenerated/**` + `permissions/schemas/schema.json`（22 个文件，实验证明构建会逐字节重建），加上 `.cargo-ok`、`.cargo_vcs_info.json`、`Cargo.toml.orig`、插件自带 `Cargo.lock`、`.github/workflows/**`（根目录之外，GitHub 永不执行）6 个文件。
3. **失效的机器特定配置**：`src-tauri/.cargo/config.toml` 的 `[source.ustc]` 没有 `replace-with`，按 Cargo 语义从不被选中；它历史上依赖的 `~/.cargo/config` 在本机已不存在。
4. **代理每次请求新建 HTTP client**：`proxy.rs` 的 `client(timeout)` 每次 `agh_fetch` 都建一个新连接池 → 无 keep-alive，多请求页面（概览页一次发 `/status`、`/stats`、`/stats_top`…）与 15s 探测每次都重做 TCP+TLS 握手；且 client 级超时与 `req.timeout(timeout)` 重复。

完成后的可观察收益：`scripts/plugin-fork-diff.sh` 一条命令给出"我们相对上游改了什么"；`git grep` 不再命中生成物与注册表残留；代理到同一实例的连续请求复用连接；文档与代码一致。

## Decision

1. **固化 fork 基线与 delta**：插件目录加 `FORK.md`（上游 `tauri-plugin-system-components` 0.1.8 + sha1 `0b05ec1ef8760bec2710d5e2a1ae64e78e76190e` + delta 清单 + 每条理由 + 上游升级步骤），加 `scripts/plugin-fork-diff.sh`：对 `~/.cargo/registry/src/*/tauri-plugin-system-components-<version>/` 跑 `diff -ru`，只输出我方增量；本机无上游副本时打印可执行的 `cargo fetch` 提示而不是报错。**sha1 必须先抄进 FORK.md，再删 `.cargo_vcs_info.json`（决策 3）。**
2. **取消跟踪构建生成物**：`permissions/autogenerated/**` 与 `permissions/schemas/schema.json` 从索引移除并加入 `.gitignore`；手写的 `permissions/default.toml` 保留——"新增命令必须同时登记 `build.rs` 的 COMMANDS 与 `default.toml`"这条既有规则不变（`docs/architecture/tauri-shell.md` 已记录）。依据：把两个目录移走后 `cargo build -p tauri-plugin-system-components` 被完整重建，且与提交内容逐字节相同。
3. **删除 crates.io 解包残留**：`.cargo-ok`、`.cargo_vcs_info.json`、`Cargo.toml.orig`、插件自带 `Cargo.lock`（与应用锁文件重复）、`.github/workflows/**`（2 个上游发布流）。保留插件 `README.md`（描述插件 API，仍有用）与 `.gitignore`（描述本地构建目录）。
4. **删除 `src-tauri/.cargo/config.toml`**：本机 `~/.cargo/config` 不存在，`~/.cargo/config.toml` 只剩 `[net] git-fetch-with-cli`；该文件的 `[source.ustc]` 无 `replace-with` 所以从不生效，Cargo.lock 里 457 个依赖全部是 `registry+https://github.com/rust-lang/crates.io-index`。它同时属于 AGENTS.md 禁止入库的机器特定配置，注释还是中文（代码注释应为英文）。
5. **代理改用共享 `reqwest::Client`**：进程内 `OnceLock<Result<Client, String>>`（保留构造失败 → 502 `KIND_NETWORK` 的分支），超时全部留在 `RequestBuilder`（client 级超时本就与请求级重复）。行为不变量不变：重定向策略 `none()` + 手动同主机跟随、25s/120s 分档、`Authorization` 只在非空时发送、失败仍产出 `{error, kind}` 而不返回 `Err`。
6. **原生控件面收敛到 iOS**（**待方向确认**，见 Note）：`useNativeBackButton` 增加 `isTauriIOS()` 判据，与 `useNativeHeaderAction` 的 `active` 判据一致；macOS 桌面壳回到 CSS 胶囊。理由：fork 新增的 `alpha`/`appearAnimation`/`appearOffsetX`/`appearDuration`/`foreground` 只有 iOS Swift 实现，`desktop/macos/components.rs` 与上游逐字节相同，macOS 上 `updateComponent(id, {alpha: 0})` 是空操作；而桌面窗口默认 960×640 **低于** `useIsDesktop` 的 1024px 断点，`tauri dev` 时会真的走到无动画的原生路径。
7. **微清理**：`proxy.rs` 抽 `net_error(e)` 合并两处相同的 `is_timeout → timeout/network` 映射；`Location` 头从两次查找合成一次；`TIMEOUT_*` 与 `agh_fetch_impl*` 的 `pub` 收窄到 crate 内；`src/lib/native/nativeTabbar.ts:92` 的中文 `console.warn` 改英文（src 层已统一过英文注释，这条漏了）。
8. **文档同步**：`docs/architecture/build-and-release.md` 的验证表删掉"先 `node scripts/mock-agh.mjs`"（契约 runner 自起 TCP origin，AGENTS.md 已写明）；`docs/native-platforms.md` 把"提供 Windows、Android、macOS、iOS 壳"改为"iOS 已交付，桌面/Android 计划中"（`gen/` 目前只有 apple，计划 Phase 4/5 未勾）；`docs/architecture/tauri-shell.md` 的插件小节补一句指向 `FORK.md`。

## Note

**本次调查的量化证据（均为实测，非推断）**

- `cargo test`：5 passed / 0 failed（4 个单测 + 1 个契约 runner）。库入口、命令面、错误语义、超时分档、重定向同主机约束均已有断言。
- 插件 fork 规模：`git ls-files src-tauri/plugins | wc -l` = 66；Rust 约 2,000 行（`models.rs` 365、`desktop/macos/components.rs` 504、`tab_bar.rs` 208、`macos/mod.rs` 245、`desktop/mod.rs` 189、`mobile.rs` 159、`commands.rs` 130、`window_glass.rs` 89、`lib.rs` 79、`error.rs` 29）；Swift + Kotlin 2,913 行。
- delta 实测（对 `~/.cargo/registry` 上游副本 `diff -rq`）：Rust 侧 `models.rs`（`foreground`/`alpha`/`appearAnimation`/`appearOffsetX`/`appearDuration` 五个字段 + `SetAppearanceOptions`）、`commands.rs`/`lib.rs`/`mobile.rs`/`desktop/mod.rs` 的 `set_appearance` 管道、`build.rs` 的 COMMANDS 一行；Swift 侧 `ComponentArgs.swift`(11) / `ButtonComponent.swift`(22) / `ComponentsOverlay.swift`(42) / `SystemComponentsPlugin.swift`(34) 共约 110 行改动。**全部是加法，不改变上游语义**——这是"跟随上游升级可行"的前提，本提案要保住它。
- fork 确实进产物（不是死代码）：`gen/apple/build/arm64-sim/AGH Console.app` 主二进制里能搜到 `appearOffsetX`/`appearAnimation`，这两个标识符只存在于我们 fork 的 `ComponentArgs.swift`。
- 生成物性质实验：`mv permissions/autogenerated /tmp && mv permissions/schemas /tmp` → `cargo build -p tauri-plugin-system-components` → 两个目录被重建，`diff -r` 与提交内容逐字节相同（`tauri-plugin` 的 `build/mod.rs` 就写这两处，build script 的 CWD 是插件 crate 根）。
- `.cargo/config.toml` 失效证据：`~/.cargo/config` 不存在；`~/.cargo/config.toml` 仅 `[net] git-fetch-with-cli = true`；Cargo 源替换要求被替换源写 `replace-with`，该文件只有 `[source.ustc] registry = …`；锁文件里除 tao 的 git 源外 457 条全是 crates.io index。
- 插件暴露面的实际使用：19 条 `allow-*` 权限里只用到 10 条（configure/remove/select/get_tab_bar_insets、create/update/remove_component、set_appearance、register/remove_listener），未调用 9 条（show/hide_tab_bar、set_badge、present/dismiss_sheet、update_components、is_glass_supported、set/clear_window_glass）；8 种组件 kind 只用到 `button`。

**明确不做：裁剪插件里从应用侧不可达的上游代码。** 约 1,400–1,500 行（Android `SheetController.kt` 447 + `SystemComponentsPlugin.kt` 146、iOS `SheetOverlay.swift` 325、`Components/TabBarComponent.swift` 203、六个小组件 200、macOS `window_glass.rs` 89，另加 Rust 侧对应模型与胶水）。理由：这是通用上游插件的上游代码，删掉会把"加法式 delta"变成"结构性 delta"，此后每跟一次上游版本都要重新做语义合并；正确做法是把"我们用到哪一面"写进 `FORK.md`，而不是裁代码。同理不裁剪 `.cargo-ok` 之外的 `android/`（Android 在计划 Phase 4，未生成工程但属路线图内容）。

**待定（决策 6 需要方向输入）**：桌面线（Windows/macOS）是否继续做。若继续，决策 6 换成"在 AppKit 实现 `alpha`/`appear*`/`foreground`"，本提案其余各项不受影响；若不做，则按决策 6 收敛到 iOS 并在 `docs/native-platforms.md` 写明桌面原生控件为 iOS 专属。倾向后者：`release.yml` 目前只产 Web 产物（`dist`+`server`），桌面不在交付面上。**决策 2–5 与 7、8 不依赖这一项，可先落地。**

**其他发现（不在本提案范围，另行处理或已知接受）**

- 契约夹具只钉"路径 → 超时档位"的规则（300ms 短档回退），25s/120s 的具体数值以散文形式写在夹具注释里、两个适配器各持一份常量（`TIMEOUT_DEFAULT`/`DEFAULT_TIMEOUT_MS`），数值漂移不会被夹具拦住。可选加固：夹具加数值字段由两个 runner 断言。归 `testing` 类，需要时另立提案。
- `AghFetchResult.content_type` 前端未消费，属已记录的允许差异（`docs/architecture/tauri-shell.md`），保留。
- 壳加固（`csp: null` + 服务端 `icon_svg` 直插 DOM + 全仓 0 处使用的 `withGlobalTauri`）是同一轮调查的另一组发现，另行登记一份 bug-fix 提案；两份共用一次壳回归，实施顺序不限（本提案的改动不触及 CSP 与渲染层）。
