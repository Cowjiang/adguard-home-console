# 修掉 iOS 原生顶栏按钮按文字固有宽度溢出、压住同槽位按钮与标题的问题

**Class:** bug-fix
**Status:** implemented
**Date:** 2026-10-18
**Source:** 用户 2026-10-18：「问题1需要改成跟web端一样两个圆形按钮，创建快照那个是绿色图标，你复盘为什么会有这个问题并一并修复其他地方」（问题来自同日基于 iOS 模拟器 + XCUITest 的实测走查）

## Goal

iOS 壳内顶栏右侧由原生玻璃按钮接管后，**原生按钮的宽度与它接管的 CSS 占位宽度不一致**：占位是 44pt 图标钮，原生按钮却是按文字固有宽度排版的胶囊。快照页因此在标题栏里丢了一个入口：原生「Create Snapshot」（实测 235–386pt，151.3pt 宽）完整盖住了同一槽位左侧的「Import Snapshot」胶囊（实测 292–336pt，44pt），点导入按钮的位置弹出的是创建面板；居中标题 `Snapshots`（158–244pt）也被压掉右端。目标：原生按钮与 CSS 占位同尺寸，并修掉同类隐患。

同时修掉这次一并查出的第二个缺陷：**顶栏槽位机制只支持一个原生按钮**（组件 id 固定 `nav-action`，插件在建组件前会先删同 id 的旧组件）。重写页「同步 + 新建」、过滤器页「同步 + 更新」在同槽位各写了一个原生规格，两个规格互相删对方的按钮，而被删那边的 CSS 占位仍然隐藏——那个操作会整个消失。快照页的「导入」也正因为这一点留在 CSS（自己写了原生也活不过创建钮）。目标：让每个槽位一个独立原生组件，两个按钮并存。用户随后直接问到了这里：「上传快照那个按钮是不是没替换成原生按钮？」

## 复盘（为什么会出现）

1. 原生按钮的尺寸由插件决定，不由 CSS 决定。`useNativeHeaderAction` 只在 `iconOnly` 为真时传 `width: 44`，否则 `ButtonComponent` 用 `UIButton.Configuration` 按 `title`/符号固有宽度布局；锚点是 `topTrailing`，因此超出的宽度全部向左溢出。
2. CSS 侧只放了一个 44pt 的**不可见占位**（`w-11`，`visibility: hidden`），标题夹取也只按这个 CSS 槽位测量（`PageHeader` 的 `ResizeObserver` 量的是 `rightRef`），DOM 里没有任何东西知道原生按钮的真实宽度。
3. 契约只写了「原生接管、自定义按钮永不显示」，没有写「原生按钮必须与占位同尺寸」；在快照页把页头操作收进标题栏之前，**没有一个槽位同时满足「原生按钮带文字标签」+「同槽位还有第二个按钮」**，所以这个不一致一直不可见。
4. 快照页（`c8e76d2` / `d9e3122`）把导出/删除/导入/创建一起搬进标题栏时，创建按钮在移动端设计上是图标钮（CSS `w-11`），原生规格却沿用了「文字按钮」的写法（`label` 无 `iconOnly`），于是原生按文字排版成 151.3pt，而它左侧恰好新出现了导入按钮——两个前提第一次同时成立，问题才暴露。
5. 槽位机制本身也只有一格：`nativeHeaderAction.ts` 把组件 id 写死成 `nav-action`，插件的 `build()` 在建之前先 `remove(id:)`，所以同页两个原生规格会互相删除；`owner` 也只是一个模块级单值。快照页的导入因此没有原生规格（写了也会被创建钮删掉），重写页/过滤器页则是带着这个隐患上线的。

同类隐患（带标签的原生按钮 + 44pt 占位 + 槽位里有兄弟按钮）：过滤器列表页的「刷新」原生规格是 `label + sfSymbol`（实测 111.7pt），左侧在同槽位有「同步」胶囊（两个及以上实例时出现），会复现同样的覆盖。纯符号、未标 `iconOnly` 的原生按钮（重写页/自定义规则页/客户端页的同步钮）按固有宽度约 44–48pt，与占位有 0–4pt 偏差，也会让兄弟按钮错位。

## Decision

1. **原生规格必须与它接管的 CSS 占位同尺寸**：移动端占位是图标钮（`w-11`，44pt）时，原生规格必须带 `iconOnly: true` 且只给 `sfSymbol`（带 `label` 会把文字塞进 44pt 里）。
2. 快照页「创建快照」按 web 端形态收敛为**绿色图标钮**（`sfSymbol: 'plus'` + `foreground: 'accent'` + `iconOnly`），与左侧导入胶囊并排成两个圆形按钮；桌面 `lg` 仍是带文字的 CSS 胶囊。
3. **槽位机制扩成一槽一 id**：`headerSlotGeometry(slot)` 给出 id（`nav-action` / `nav-action-2` / …）与横向偏移（每格 44pt + CSS 间隙 6px），`owner` 改成按 id 记的 Map；`NativeHeaderSpec.slot` 表达「从右往左第几个」。快照页导入补上 `slot: 1` 原生规格，两个按钮这时才真正并排成原生玻璃钮。
4. 同槽位的同步胶囊（过滤器列表页、重写页、客户端页）与它右侧的原生按钮一起改：左侧那个 `slot: 1` 并给原生规格——顺带修掉重写页/过滤器页两个原生规格共用 `nav-action` 互相删除的缺陷。
5. 不引入「把 CSS 占位宽度传给原生按钮」的机制（文字按钮按占位宽度排版会裁字），改由约定 + 文档约束：只有槽位里唯一的操作可以是文字原生按钮（设置页「保存」、实例页「管理/完成」）。
6. 顺手修掉同批走查发现的另外两处不一致：快照卡备注按文档单行截断；`SnapshotCreateForm` 的过期注释（仍在描述已被否决的 `/settings/snapshots/new` 子页形态）。

## Note

- 实测几何（iPhone 18 Pro，402×874pt，XCUITest 层级 dump）：原生创建 235–386pt / Web 导入 292–336pt / 标题 158–244pt；点 (314,92) 打开的是原生创建面板。
- 修复后复测（同一台模拟器、同一份 dump）：快照页原生创建钮 `{342,70,44,44}`（label `add`），导入胶囊 `{292,70,44,44}` 恢复可见可点（点它不再打开创建面板）；过滤器页原生刷新钮从 `{274.3,70,111.7,44}` 收到 `{342,70,44,44}`，标题有完整空间。
- 扩槽位后复测：快照页同一窗口内三个原生控件——返回 `{16,70,44,44}`、导入 `{292,70,44,44}`、创建 `{342,70,44,44}`；两个实例时过滤器页同样并存「同步 `{292,70,44,44}` + 刷新 `{342,70,44,44}`」（此前两个规格共用 `nav-action` 会互相删除）。
- 图标钮的朗读文案：插件原本没有 `accessibilityLabel` 属性，UIKit 会回落成 SF Symbol 自己的名字（实测 `arrow.up.doc` 读作 “Previous Page”、`arrow.plus…` 无、`plus` 读作 “add”）。已给插件补 `accessibilityLabel`（Rust 字段 + Swift 解码与赋值），前端把 CSS 按钮的 `aria-label` 透传过去，图标钮与文字钮现在都报真实动作名。delta 已记入插件 `FORK.md` 与 `docs/architecture/tauri-shell.md`。
- 取证截图（本机忽略材料）：`_probe/ios-docs-check/01-snapshot-header-covered-import.png`、`01b-tap-import-opens-create-panel.png`、`07-snapshots-fixed.png`、`08-filters-fixed.png`。
- 原生图标钮的朗读文案由插件新增的 `accessibilityLabel` 承载，前端从 CSS 按钮的 `label` 透传；插件 delta 保持纯加法，便于上游发版时机械重放。
