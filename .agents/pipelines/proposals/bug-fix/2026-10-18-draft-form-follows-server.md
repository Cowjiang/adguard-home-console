# 修掉设置页草稿在服务端配置变化后停在旧值、并挂出假未保存标记的问题

**Class:** bug-fix
**Status:** implemented
**Date:** 2026-10-18
**Updated:** 2026-10-18（登记并实施：`useDraftForm` 跟随规则 + 判据表单测；验收在真实 AGH v0.107.79 上用真实前端跑完，另冒烟查询与统计页）
**Source:** 用户 2026-10-18 报告：「创建快照 → 改 DNS 上游并保存 → 恢复该快照 → 回 DNS 设置页，内容还是改后的值」（同日本机用真实 AGH v0.107.79 + 真实前端复现）

## Goal

快照恢复**在服务端是生效的**，但用应用内导航回到 DNS 设置页后，上游仍显示恢复前的值，并且页面底部挂着「放弃更改 / 保存更改」——即应用已经拿到服务端的新值，只有草稿停在旧值。目标：草稿在用户没编辑时跟随服务端副本，消掉这一类「显示旧值 + 假未保存标记」，同时不破坏「用户正在编辑时后台刷新不得覆盖草稿」的既有语义。

这不是快照专属缺陷：`src/lib/useDraftForm.ts` 被 DNS、查询与统计（两个草稿）、加密、访问控制五处设置页共用，任何「别处写入配置 + 该页当时未挂载」的组合（另一台设备、多实例同步、服务端自己改配置）都会命中同一现象。

## 复盘（为什么会出现）

1. `useDraftForm` 的投影 effect 只认 `draft === null`：草稿在**首次拿到 data 时被固定**，此后任何新 data（SWR 后台校验落地）都不会再投影，页面因此永久停在旧值。
2. SWR 的行为是「先用缓存渲染、再后台校验」，所以「页面挂载瞬间的缓存是旧的」本身是正常状态；旧代码把这个瞬态变成了终态。
3. `dirty` 是「草稿 vs 当前服务端副本」的比较，因此陈旧草稿会被判成「用户未保存的修改」——除了显示错值，还会诱导用户点「保存」把恢复前的旧值写回服务端（推论，未实测）。
4. 快照路径特别容易命中：恢复后 `SnapshotDiff` 只有一句 fire-and-forget 的 `void mutateInstanceData(cfg)`，而该 key 当时没有挂载组件；回到页面时缓存仍是恢复前的值（实测恢复完成 3.5 秒后回页仍是旧值，且 `dirty` 为真）。

## Decision

1. **hook 增加显式的「用户是否编辑过」标志**：未编辑过的草稿跟随最新服务端载荷（重新投影）；编辑过的草稿不被覆盖，只在它重新与服务端副本一致时交还跟随权（手工改回原样、或服务端追上了用户的值）。
2. **规则抽成纯函数决策表 `draftFollow({ edited, isNewPayload, matchesServer })`**，在 `src/lib/useDraftForm.ts` 内导出并配表驱动单测——仓库的 vitest 只有 node 环境（无 jsdom / @testing-library），hook 本身不可测，判定逻辑必须离开 hook 才能有回归信号。
3. **对外的 `draft` / `dirty` / `patch` / `reset` 签名与 `dirty` 语义不变**，五处设置页零改动；`patch` 置位、`reset` 清位（`reset` 必须先更新投影基线再清标志）。
4. **不动的事**：不把 `SnapshotDiff` 的 fire-and-forget mutate 改成 `await`（只缩小竞态窗口，且未能证实 SWR 的过滤式 mutate 对未挂载 key 会真的重取）；不引入 jsdom / @testing-library；不代各页面处理没放进草稿的局部页面状态（如加密页的证书来源单选）。

## Accept

- [x] 走用户报告的路径（全程应用内导航，不整页刷新）：恢复快照后回 DNS 设置页，页面在挂载时的后台校验落地后收敛到恢复后的值，且不出现「放弃更改 / 保存更改」（实测：回页约 1–4 秒内收敛，取决于该 key 的往返；修复前是永久停在旧值）
- [x] 同类场景：外部改写配置 → 该页不在挂载状态 → 回页，后台校验落地后页面自行收敛到服务端值（实测 1 秒内，`dirty` 为假）
- [x] 用户编辑草稿期间后台刷新不覆盖草稿（实测：手工 focus 触发校验，`/dns_info` 已返回服务端新值，草稿仍是用户输入且 `dirty` 为真）；「放弃更改」后回到服务端值

- [x] `docs/engineering.md`、`docs/web-interaction.md` 的草稿约定与新规则同步
- [x] 回归冒烟：查询与统计页（双草稿）切走再回来，未保存的开关被服务端副本取代、页面无残留脏态

## Note

- 复现证据（本机，一次性 AGH 实例，用完即删）：真实 AGH v0.107.79 上按用户步骤操作，恢复后直接查 `/control/dns_info` 得到 `["1.1.1.1"]`（服务端确已回滚）；同时应用内回到 DNS 页显示 `8.8.8.8 / 1.0.0.1` 且 `dirty` 为真；等待 5 秒不自愈，**再一次重新挂载该页才显示 `1.1.1.1`**。
- 判定 `dirty` 为真是关键判据：`dirty` 为假说明 data 也还是旧值，为真才说明 SWR 已拿到新值、只有草稿停在旧值。
- 复现踩坑：首次尝试用整页跳转（`goto`）回 DNS 页复现不出来——整页加载会清空 SWR 缓存，所以必须用应用内导航；这条已写进验收步骤。
- 修复后复测（同一实例、同一路径）：回页时用页面侧请求探针确认 `GET /api/agh/dns_info` 返回恢复后的 `1.1.1.1` 并落进页面；此前该页停在旧值，是因为草稿只在挂载瞬间投影一次。
- 修复前 `dirty` 的假阳性会诱导用户点「保存」把恢复前的旧值写回服务端（例如通用设置页只对 dirty 的分区发 PUT）；本提案消掉了这个入口，未单独实测该写回路径。
- 上游约定出处：`docs/engineering.md` 的「变更编排与乐观更新」原本只写了「保存成功后先 await refetch 再回填草稿」，没写未编辑时是否跟随，本提案补齐该约定。
